Flask (Python)
@app.route('/hello') def hello(): return 'Hello!'
Express (Node.js)
app.get('/hello', (req, res) => { res.send('Hello!') })
Method is set via methods=[...] on the decorator. GET is the default.
Method is the function name itself — app.get(), app.post(), app.delete().
URL parameter
@app.route('/user/<int:id>') def user(id): return f'User {id}'
URL parameter
app.get('/user/:id', (req, res) => { const id = req.params.id res.send(`User ${id}`) })
Flask uses <type:name> syntax. Type conversion and validation happen automatically — /user/abc returns 404 if type is int.
Express uses :name syntax. All params are strings — you must validate and cast manually: parseInt(req.params.id).
POST route
@app.route('/login', methods=['POST']) def login(): ...
POST route
app.post('/login', (req, res) => { ... })
One decorator handles all methods. Logic for GET vs POST lives inside the function using request.method.
Separate functions per HTTP method — no branching needed inside the handler.
Query params
from flask import request q = request.args.get('q', '') # GET /search?q=flask
Query params
const q = req.query.q ?? '' // GET /search?q=express
request is a global-like object imported from Flask — available anywhere in the request context.
req is passed directly as a parameter into every handler function.
JSON body
data = request.get_json() name = data['name']
JSON body
// Needs middleware first: app.use(express.json()) const { name } = req.body
JSON parsing is built into Flask. get_json() returns None if body isn't valid JSON.
You must register express.json() middleware first. Without it, req.body is undefined.
Form data
name = request.form['name']
Form data
// Needs middleware first: app.use(express.urlencoded( { extended: true } )) const name = req.body.name
Form parsing is built in — no setup needed.
Requires express.urlencoded() middleware. Form data also lands in req.body, same as JSON.
Plain text
return 'Hello!'
Plain text
res.send('Hello!')
Flask returns by returning a value from the function — feels like normal Python.
Express sends via res.send() — the function doesn't "return" the response; it calls a method on the response object.
JSON
from flask import jsonify return jsonify(name='Alice')
JSON
res.json({ name: 'Alice' })
jsonify() sets Content-Type to application/json automatically.
res.json() does the same — slightly more concise since JS objects are already JSON-friendly.
Status code
return jsonify(msg='Created'), 201 return 'Bad request', 400
Status code
res.status(201).json({ msg: 'Created' }) res.status(400).send('Bad request')
Status code is the second element of a return tuple — clean and readable.
Status is chained before the send method. Easy to forget — defaulting to 200 silently.
Redirect
from flask import redirect, url_for return redirect(url_for('home'))
Redirect
res.redirect('/home')
url_for() generates URLs from function names — safer than hardcoding paths.
Express redirects to a raw path string. No built-in reverse URL lookup.
Deep differenceSync vs async by default
Flask runs synchronously by default — one request is handled at a time per worker. Express is built on Node.js's event loop, handling many requests concurrently without blocking. For I/O-heavy apps (databases, APIs), Express naturally scales better out of the box. Flask can use async with async def + an ASGI server, but it's not the default mindset.
Deep differenceRequest context vs explicit passing
Flask uses a request context — the request object is a thread-local global you import. It feels magical but can confuse beginners. Express passes req and res explicitly into every handler — more verbose but completely transparent. No hidden state.
Deep differenceBatteries vs middleware
Flask includes form parsing, JSON parsing, and session handling out of the box. Express ships as a minimal core — almost everything (JSON body, cookies, sessions, CORS) requires installing and wiring up middleware via app.use(). Express is more flexible; Flask is faster to get started.
Syntax differenceURL parameter typing
Flask supports typed converters like <int:id> — invalid types auto-404. Express uses :id (always a string), so you must validate and cast manually. Flask's approach means less defensive code in your handlers.
Syntax differenceHow responses are sent
Flask uses Python's return statement — responses feel like normal function output. Express uses res.send() / res.json() methods — the handler doesn't "return" anything meaningful; it calls methods on a response object. Forgetting to call res.send() in Express leaves the request hanging silently.
BothRouting structure
Both support route grouping: Flask uses Blueprints, Express uses Routers (express.Router()). The concept is identical — split routes into separate files/modules. The APIs are different but the mental model is the same.
